# C4 income fields, migration and new totals outputs

- `src/state/income-migration.js` filled: `needsIncomeMigration`, `migrateIncomeFields`, `acceptPayslipJob` (for C8). Per source: `hourlyRate`, `hoursPerWeek`, `superPct` (null), `basis` (`salary` | `selfEmployed` | `variable`), `taxCheck` (null), `withholding {claimsTaxFree:true, hasStudyDebt:null, medicareExemption:false, extraPerPay:0}`. Guard: a source is touched only while it has no `withholding`, so it is idempotent and a dismissed prompt never returns. Nothing is removed or edited.
- A self-employed source with tax withheld, a net pay and a known pay cycle gets `migrationPrompt:'payslip-job'` and nothing else changes (698 x 26 = 18,148 before and after). Variable sources and self-employed sources with no tax are never flagged.
- `taxBrackets` is copied once to `legacyTaxBrackets` and left in place; neither it nor `taxSettings.financialYear` is read by anything new. No year or `yearMode` is stored (FT-R-86). No `nextPayDate` (X-9: `payAnchor` is the one field).
- `calculations.js`: new outputs only. Per source `_withheldPerCycle` and `_netPerCycleWithheld` (actual payslip tax when entered, else the C2 engine for a source with a declaration; null for variable). Totals gain `_annualTaxOwed` and `_refundOrBill` (C3, HELP per source from `hasStudyDebt`, FT-R-75 D10). Optional second argument `{today}` picks the tables. All existing outputs identical.
- `defaults.js`: new default source carries the new fields.
- Fixture only: `chain.test-cases.js` `settledData` source now carries `withholding` (as B3 did for `dataVersion`); no assertion changed.
- Medicare exemption and salary sacrifice are stored/asked but not modelled (FT-R-67).
- Removed feature: **custom tax brackets** (FT-R-97). Tax always comes from the dated ATO tables; the old saved set is kept as `legacyTaxBrackets` and never read.
- Tests: 9 cases (45 assertions) in `income-migration.test-cases.js`; `tests.html` 1031 to 1076.
