# F1 Scenario model and store

- `src/calc/scenario.js` replaces the M0 stub body (`resolveAt` and `segments` keep their signatures). A scenario is a list of dated changes `{id, kind, target:{collection,id}|null, field, op, value, baseValue, from, until, note}`; kinds income, expense, split, goal, goalFund, incomeAdd, debtAdd, oneOff, assumption; ops set, scale (value is a FACTOR, 1.1 = +10%), add, remove. Targets by id; a missing target is skipped (`missingTargets` lists them for "no longer in your plan"); rows with no id or role never throw.
- `resolveAt` returns a transient `structuredClone` (not a JSON clone: the tax bands' Infinity survives) with every change active on the date applied in list order (`from <= date < until`). Virtual results added only on demand: `scenarioOneOffs` `[{id, amount, date, note}]` and `scenarioGoalFunds` `[{collection, id}]`. goalFund: target `{collection:'assets'|'allocation', id}`, ticked on unless `op:'remove'` or `value:false`.
- `segments(changes, from, to)` returns `[{from, to, key}]` (`to` exclusive, `key` = active change ids); `breakpoints`, `resolveSegments` (resolves once per key). Also `conflictFor` (`{conflict, live, scenario}`), `conflictsFor`, `changeProblems`, `isActiveOn`, `applyOp`, `scenarioHeadline(summary)` (returns `{kind, key, params}`; goal verdict, else FI years, else left per pay), `makeRealPlan` (now, later, droppedUntil, missing, conflicts; steps carry a route).
- `src/state/scenarios.js` (new): the store (`listScenarios`, `getScenario`, `saveScenario`, `duplicateScenario`, `renameScenario`, `pinScenario`, `archiveScenario`, `newScenario`), restore sanitizer (G6: ids, caps, prototype keys, bounded numbers, bad changes dropped and counted), the `scenarios` backup part (registered through D2's `registerBackupPart`, so export, restore and erase-all need no other change), and `applyMakeReal` (plan items via B4, split and goals via E5, FI assumptions direct; one combined undo payload; no timer).
- `db.js` DB_VERSION 1 to 2 with the `scenarios` store behind `objectStoreNames.contains`. `backup.js`: `cleanValue` is now exported (one word). `import-export.js` imports `scenarios.js`; `settings-events.js` erase-all dynamically imports it first so the part is registered.
