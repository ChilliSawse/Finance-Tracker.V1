# F2 asset and debt detail: schema, migration, maths

- `src/calc/assets-debts.js` (new, pure): `effectiveAnnualRate` (`(1 + r/n)^n - 1`), `interestEarned`, `dividendsFor`, `realRate`,
  `depreciatedValue` (purchase price and date; the entered balance stays the truth), `depreciationDiffers` (the 5% "use A$X" test for F5),
  `assetValueAt` (cash, invested, appreciating, depreciating; a suggested kind or an unset rate is flat, 0% real), `debtRateAt`,
  `debtStep` and `debtSchedule` (integer cents, one rounded interest figure a period, fixed rate until `fixedUntil`), `suggestKind`,
  `suggestLabel`, `VEHICLE_DEPRECIATION`.
- `src/state/asset-debt-migration.js` fills M0's stub (chain step 5b; wiring and the backup condition were already in `migration-chain.js`, untouched).
  Guard `assetDebtVersion >= 1`. The chain's existing backup writes the raw old save byte for byte first (`ft-backup-pre-plan`).
  Totals check (assets, liabilities, `calculateTotals(clone).netWorth`, in cents) throws on a mismatch, so the chain aborts, nothing is
  committed and `assetDebtVersion` is not written.
- Every field the migration writes (only when absent; names, balances and existing rates are never touched):
  `assetDebtVersion` (1, last), `fiSettings.inflation` (2.5), `incomeSources[i].id` (`inc-<slug>`),
  assets: `id` (`a-<slug>`, `-2` on collision), `kind`, `kindSuggested`, `isSuper`, `interestFrequency` ('monthly'), `expectedReturn`,
  `dividendYield`, `growthRate` (null), `dividendFrequency` ('quarterly'), `reinvestDividends` (true), `depreciation` (null, or the vehicle
  default record 25% / 8 years for a suggested depreciating asset);
  liabilities: `id` (only when missing, `newLiabilityId`), `interestType` ('variable'), `fixedUntil`, `rateAfterFixed`, `minRepayment` (null),
  `compounding` ('monthly'), `repaymentFrequency` ('monthly'), `label` (suggested or null), `labelSuggested`.
  An unset asset `interestRate` is left absent, not null: S1.8 requires every `interestRate` key to be a finite number.
- Sample: only the asset rate fields (savings 4.8% monthly, ETF yield 3.5% quarterly). The sample build deletes `assetDebtVersion` so the chain
  migrates it on first load (ids and suggested kinds). `legacySampleFinanceData` (the old-shape fixture) also drops `assetDebtVersion` and `fiSettings.inflation`.
- `defaults.js`: new data carries `assetDebtVersion: 1`, `fiSettings.inflation: 2.5` and an id and kind on the placeholder asset, so default data
  needs no backup (B3.4 stays as written). `bucket-migration.js`: `slug` is exported (one word) so ids use one owner. `chain.test-cases.js`:
  fixture `settledData` gains `assetDebtVersion: 1` (no assertion changed).
- `tools/dry-run.mjs`: tables of assets by kind and debts by label, before and after, the suggested counts, id gaps, three new checks; the
  amount lines (assets by kind in A$) sit in section (b) and disappear with `--no-amounts`.
- U35: ATO effective life for cars is 8 years; since 10 May 2006 the diminishing value rate is 200% / life = 25% and prime cost 100% / life = 12.5%.
  Confirmed from ATO search results (the ATO pages returned 403 to a direct fetch, so the page text itself was not read). The car limit cap is not applied.
  Source URLs are in the comment on `VEHICLE_DEPRECIATION`.
- U37: C4 does not add `incomeSources[i].id` (its migration touches `withholding`, `hourlyRate` and friends only). F2 adds them; the guard-by-absence means order is irrelevant.
