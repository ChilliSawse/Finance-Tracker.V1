# E5 saving-model state API and `getBuckets()`

- `src/state/saving-model.js` replaces the M0 stub. `getBuckets(data, today)` returns the section 9.1 shape: top-level rows, each followed by its goals and sub-buckets (`kind:'goal'`, `parentId`); Fire carries the active `target`, Mojo its ladder step, `goal`/`left` where a goal exists. Tolerant of rows with no id or role.
- State API, all `(data, ...)`, mutating in place, returning B4's `{ok, message, onUndo, onExpire, ...}` (failed calls change nothing and carry a `code`): `newBucket`, `addBucket`, `renameBucket`, `setSplit` (writes only at 100), `applySuggestedSplit`, `forkOwnTemplate`, `switchBackToBase`, `canReturnToBase`, `deleteBucketWithMove` (asks "Move A$x to..." via `code:'move'`; resets category and plan links), `addGoal`/`updateGoal`/`setGoalShares`/`removeGoal` (shares rebalance to 100), `moveTarget`/`skipTarget`/`addTarget`/`removeTarget`/`applyCashToTarget`, `setMojo`/`addMojoStep`/`removeMojoStep`, `relinkCategory`, `tickTransfer`, `setAutoCredit`, `rollPayDays`, `runPayRollIfDue`.
- Never blocks: an out-of-template add or delete returns `needsFork:true` with nothing written; `{fork:true}` forks and applies in one undoable step.
- Auto-credit: off does nothing; enabling clears the old marker so the first roll sets it with no retro credit; a second run on the same day is a no-op; a marker saved ahead by another tab skips the roll (U17).
- `main.js`: one `runPayRollIfDue` call after `loadData`, one `visibilitychange` listener.
- `settings-events.js`: `bucketGoals` whitelisted; `addAllocationCategory`/`removeAllocationCategory` use the API for live data (undo toast) and `newBucket` for What If.
- Strings in `src/i18n/en-e.js` (`e.*`). Tests: 69 assertions in `state-api.test-cases.js` (T19, E5.1 to E5.4 and the rest); `run-cases` 887 to 956, `tests.html` 1169 to 1238.
- Contract note: the E5 wrapper is named `rollPayDays`, not `runPayRoll`, because the gate rejects a second exported `runPayRoll` (E2's is in `calc/pay-roll.js`).
