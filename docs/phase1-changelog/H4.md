# H4 Setting a pay date on the Salary sheet said "Could not save" (live bug fix)

Reported on iPhone after 2.0.0: setting the pay date to 2 December 2026 and tapping Save showed "Could not save. Nothing was changed."

## Root cause

Not iOS-specific, and not the date. Every save from the Salary and Set-hours sheet failed, on any browser. `persist()` in `src/ui/income-layout.js` called `renderIncomeSourcesSettings` from `settings-forms.js`. A12b deleted that function but left the call. After the values were written to the source in memory, the call threw `TypeError: t is not a function` (the minified name of the missing function), before `updateDataAndUI` could save. `sheet.js` caught it and showed the message. Reproduced on the live build (777a142) at 390 wide with touch, Australia/Melbourne, using his backup.

Routes on his data (migrated Self-employed income, with the "switch to Salary" offer):

| Route | Live 777a142 | Before H4 (branch) | After H4 |
|---|---|---|---|
| Plan, income, "Switch to Salary", date, Save (also the Salary sheet) | fails | fails | saves, type Salary, pay anchor stored |
| Self-employed editor "Next pay day" (H1) | field not there | saves | saves |
| Today "Set your pay day" | opens Plan sheet (no field) | opens Self-employed sheet, saves | saves, full Today dashboard |

The H1 Self-employed route never touched the broken function (its own `persist` in `income-other.js` is fine), so it works on his data.

## Why his income showed as Self-employed

Not set by the new migration. His backup already stores the income as Self-employed. The older `migrateIncomeSourceTypes` (`src/state/migrations.js`) deliberately turns every old-format source without a type into Self-employed (the old engine never deducted tax brackets). The newer income migration (`income-migration.js`) only adds fields and flags a payslip-like source with the "switch to Salary" offer; it does not change the type. So the mapping is by design, not a new fault. Left unchanged: changing it would alter already-migrated data. If wanted, a later decision could offer Salary for any old-format source with a gross figure.

## Changes

- `src/ui/income-layout.js`: `persist()` no longer calls the removed function (exported). The sheet's save is now an exported `saveIncomeSheet(ctx, values)` that the sheet's `onSave` calls.
- `src/ui/sheet.js`: the failure path now logs one line of JSON: error type, first 160 characters of the message, top 5 stack frames, field keys. No values, no names.
- Test: `income-layout` "H4" runs `saveIncomeSheet` for an accepted migrated source with the 2 Dec date and checks no throw, the stored anchor, and that autosave ran. It fails on the old code with `renderIncomeSourcesSettings is not a function`.

A scan of every `import { ... }` and `await import()` destructure in `src` found no other name that the target module does not export.

## Not verified

The iPhone itself. The failure reproduces identically on desktop Chromium, so no iOS-only cause is needed. Date parsing uses `YYYY-MM-DD` strings and local-date helpers, and nothing locale-sensitive was in the failing path.
