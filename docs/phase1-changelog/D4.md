# D4 acceptance harness, preview scripts, width sweep and the tests gate on deploy

- `tools/accept.html` (not shipped: `vite.config.js` inputs are only `index.html` and `tests.html`; confirmed `dist/` has no `accept.html`). Run `npm run dev`, open `/tools/accept.html`, pick a bank CSV, XLSX, PDF statement or payslip PDF. The real `parseCsv`/`detectColumns`/`normaliseRows`, `readXlsx`, `extractPagesLines`/`parseStatementPages` and `parsePayslipLines` run in the tab; nothing is uploaded. Buttons run it on synthetic CSV, XLSX, statement PDF and payslip PDF fixtures built in the page. "Copy report" copies the text.
- `tools/accept-core.mjs` builds the report: row count, first and last month, sign split (counts), duplicates on re-import (real `addTransactions` run twice on a scratch IndexedDB `ft-accept-scratch`, deleted after; the app's own database is never opened), unparsed line count, detected bank or provider, schedule, fields found as booleans. The report object holds integers, booleans and members of fixed lists only (bank names from `BANK_CONFIGS`, payslip providers, schedules); `renderReport` prints fixed labels, re-checks months with a regex and falls back to `unknown`/`none` for anything not on a list. Error messages from a failed read are never shown (only the error class).
- `tools/accept-fixtures.mjs`: synthetic CSV, XLSX rows, statement page lines, payslip lines, and a tiny PDF writer; fake name and fake account number are included on purpose for the privacy test.
- `tools/serve-preview.sh` and `.ps1`: serve `dist` with `python -m http.server` on the first free port in 8700-8799, bound to the tailnet IPv4 (`tailscale ip -4`; falls back to 127.0.0.1, or `--local`/`-Local`). They print `tailscale serve --bg --https=8449 http://<ip>:<port>`, `tailscale serve status` and `tailscale serve reset`; they never run `tailscale serve`. Tested locally (plain serve returns 200; the tailnet bind printed 100.x). The https trial for U20 and U21 is Chilli's check 5.
- `tools/sweep.mjs`: the width sweep from `mockup/bakeoff/_review.js`, adapted: 360, 390, 768, 1024, 1440 wide, screens today, activity, plan, future, settings on the sample household; screenshots, horizontal overflow (with the first overflowing element's tag and class), page errors, external requests; exits 1 if anything is flagged. `--dark`, `--out`, `--url`.
- `tools/static-server.mjs`: shared tiny static server for the two Playwright tools.
- `.gitignore`: `real-files/`.
- **Deploy gate (FT-R-100):** `tools/ci-tests.mjs` (`npm run test:ci`) serves `dist`, opens `tests.html` headless and exits 1 unless `#summary` has class `pass` and reads `All N tests passed.`; also fails on an uncaught page error, a missing build or a timeout (180 s, `CI_TESTS_TIMEOUT_MS`). `.github/workflows/deploy.yml` build job: `npm ci`, `npm run build`, `npx playwright-core install --with-deps chromium`, `npm run test:ci`, then the Pages artifact upload; `deploy` needs `build`, so a red suite means no deploy. Workflow YAML parsed with the `yaml` package (outside the repo): 7 build steps, deploy needs build. The real GitHub run still has to be done on a throwaway branch with Chilli's OK; it was not run here and nothing was pushed.
- **G2, new devDependency `playwright-core` 1.65.1 (pinned exactly, lockfile updated):** on npm since 2020, maintained by Microsoft (maintainers include `microsoft-oss-releases`), repository `github.com/microsoft/playwright`, Apache-2.0, zero dependencies, 1.65.1 published 2026-11-13 (npm registry, 2026-11-21), signed tarball. Chosen over `playwright`/`@playwright/test` because the gate needs only the library and the browser installer (`playwright-core install`), not the test runner or its extras. M-8's "no Playwright" line in G2 is superseded by FT-R-100. `npm audit` reports the same 13 transitive findings (fast-uri, workbox chain) with and without this change.
