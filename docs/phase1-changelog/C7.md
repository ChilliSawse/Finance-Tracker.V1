- `src/ui/onboarding.js` rewritten: full-screen setup in `#setup-root` (FT-R-69), one step at a time, Back, Skip this step, Close, progress bar, focus moves to the step heading, `inert` on `.app` while open. First run (no saved data and no `ft-onboarded`) opens a welcome with Set up my numbers, Explore with sample data (`loadSampleData`, unchanged call) and Skip for now. `ft-onboarded` is still read and written, so nobody who finished the old onboarding sees setup again. Settings > Run setup again (`ledger:run-setup`, D2) opens it with no welcome and no sample button (sample data would replace their data).
- Step registry (X5), `src/ui/setup/registry.js`: `registerSetupStep({id, order, title, render, validate, onNext, ...})`, `getSetupSteps()`. Extras: `onBack`, `actions` (delegated `data-su-act` / `data-su-change`), `skippable`, `nextLabel`. `STEP_ORDER`: model 10, quiz 20, layout 30, pay 40, essentials 50, nonEssentials 60, debts 70, split 80, transfers 90, first 100.
- E8 NOTE: C7 ships working `model`, `split` and `transfers` steps (`steps-basic.js`) registered with `{defaultOnly: true}`. E8 registers its own under the same ids with a normal `registerSetupStep` call and replaces them whatever the load order. The default split previews `applySuggestedSplit` on a copy and saves it on Next only while the split is still the book's 60/10/10/20.
- Quiz (`quiz.js`, FT-R-30): jobs, how paid, same each time, do hours change; per job; other income is never asked. Layouts: Salary and Set hours open C6's `openIncomeSheet`; Shifts and Business open the existing income form with "full layout coming" (FT-R-68). GST not asked (nothing in phase 1 stores it). Answers are prefilled from saved data on a re-run and never remove a source or a figure.
- `steps-pay.js`: `layout` (one card per job) and `pay` (take-home from `netPerPayCents`, next pay day from `nextPayDates`, tax-time refund or bill from `_refundOrBill`, a "Set your pay day" nudge, "Check against a payslip" opens C6's sheet).
- `steps-money.js` (M-15): essentials (bills included) and non-essentials reuse A9a's `planItemSheetSpec` and `savePlanItem` (so every write goes through B4's `addPlanItem`), category choices cut to the step's side of the `essential` flag; Edit and Remove (undo toast) per row; quick-start chips. Debts: `makeDebt` (E4's `newLiabilityId`; balance in A$, `interestRate` percent a year, `minRepayment` A$ a month; the untouched placeholder liability is replaced), Edit, Remove with undo, and a HELP balance row when a job says it has a HELP debt (`taxSettings.helpBalance`). F5 repoints `makeDebt` to `newDebt`.
- Closing step: "Log your first expense or import a statement" with Log an expense (closes setup, opens Quick-add) and Import a statement (clicks `#open-import`).
- Today checklist (`checklist.js`, A6's `#today-setup-slot`, rendered by one call at the end of `renderToday`): pay, essentials, non-essentials, debts, split, transfers, first expense. Done comes from the data where it can, else from the steps finished; skipped steps stay to do with a "Not needed" link; "Hide this list". Only exists once setup has been started in this version (new key `ft-setup-state`), so existing users never get one; hidden on the sample household.
