# C5 payslip check and HELP row

- New `src/calc/payslip-check.js` (pure): `checkPayslip(payslip, source, {today})` returns `{matches, expected, diff, tolerance, likelyCause, message, fix, useActuals, unexplainedPerPay, payslipIsTruth, grossProposal, breakdown}`; `toleranceFor(cycle)`. Expected = C2 component sum (FT-R-68), tax year from the payslip's own date (FT-R-86). A payslip dated before 2025-09-24 returns `payslipIsTruth` (FT-R-75 D6).
- Tolerance = ceil(weeks per pay) dollars: weekly 1, fortnightly 2, monthly 5, quarterly 13. A monthly 2026-27 pay (gross 6,101, HELP) has component 1,214 vs combined 1,209, a A$5 gap, and still matches.
- Causes in order: `help`, `no-help`, `tft-claimed` (stored threshold flag looks wrong, optionally with a HELP flip in `fix.also`), `medicare-exemption` hint, `salary-sacrifice` (implied amount searched), `overtime` (payslip gross above stored), `extra-withholding`; otherwise `{cause:null, useActuals:true, unexplainedPerPay}`. Each cause carries a data-only `fix` descriptor `{action, field, value, labelKey}`.
- A gross on the payslip that differs from the stored one is only a `grossProposal {needsConfirm:true}`; nothing is written by this module.
- `payslip.js`: new `help` field (HELP, study loan, STSL, HECS rows) and `grossDerived` flag (gross estimated from net + tax, so callers can show it before replacing a stored gross). Existing fields and assertions unchanged.
- Strings: `c.payslip.*` in `src/i18n/en-c.js`. Tests: 10 cases (52 assertions) in `payslip-check.test-cases.js`; run-cases 887 to 939.
- Reconciled: P1 698 = 626 + 72, P2 diff 72, P4 expected 848 diff -150, P5 674 (2026-27) tolerance.
- Judgement calls: the Medicare hint is tested before salary sacrifice (sacrifice search would otherwise always win a negative gap). `extra-withholding` fires for any unexplained positive gap up to the expected tax, and the stored `extraPerPay` is already inside `expected` (C2), so a declared extra matches rather than being a cause.
