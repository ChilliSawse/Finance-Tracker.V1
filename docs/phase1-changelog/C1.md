# C1 tax tables keyed by date

- New `src/calc/tax-tables/` (`au-2025-26.js`, `au-2026-27.js`, `index.js`): one dated data file per
  income year with `fy`, `effective`, `sources`, `updated`, withholding `scale1`/`scale2`, `stsl`
  (TFT claimed / not claimed), `brackets`, `medicare`, `help`, `lito`. Rows are the P0.5 confirmed
  figures (F2025L01016 post 24 Sep 2025, F2026L00716, NAT 1004, NAT 3539, HELP gazette C2026G00249).
- Registry exports `TAX_TABLES`, `taxYearKeyForDate` (1 July rule), `getTablesForDate` (undefined when
  none shipped), `resolveTablesForDate` (latest with `stale:true` past the tables) and
  `taxTablesStatus(now, data)` giving `{activeFy, stale, checkDue}`.
- `tax-au.js` is additive: `AU_TAX_YEARS` is now the registry (same brackets, Medicare, HELP values),
  `CURRENT_TAX_YEAR` still exported, and `getTaxYear` falls back by date for an unknown or absent key
  (the one behavioural change; same result today). It also re-exports the new date functions.
- Medicare stays A$28,011 for annual assessment; the schedule's A$26,000 is inside the scale 2 rows.
- Existing tax assertions in `tests.html` are untouched. Tests: 6 cases in `tax-tables.test-cases.js`.
