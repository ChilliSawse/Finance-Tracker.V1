# E2 Fire, Mojo and pay-roll maths (pure)

- New `src/calc/fire.js`: `defaultFireTargets` (debts smallest first, ties higher rate; then Mojo, Home deposit, Super; no HELP),
  `fireStatus` (one active target, auto-skip of deleted or zero debts, the `mojo-under-starter` note flag), `payoffPays`,
  `applyPay` (interest `round(rem x r)` half up in integers, once per pay on the active debt; overflow carries on with no
  interest that pay), `rebaseTargets`, `mojoLivingCosts` (essentials; planned until 2 full months, then actual), `mojoSteps`.
- New `src/calc/pay-roll.js`: `runPayRoll(data, today, opts)` returns `{data, changed, paysApplied, skipped}`; never mutates its input
  and returns the same object when nothing changed. Marker `autoCredit.rolledThrough`, catch-up cap 52 (latest pays win),
  movements capped (count and 24 months), first enable sets the marker with no retro credit, `on:false` does nothing.
- Shapes chosen here (E4/E5 please follow): savingModel money is cents: `fire.targets[]` use `startCents`, `remainingCents`,
  `balanceSeenCents`, `savedCents`, `goalCents`; `mojo = {starter (cents), months, basis, steps:[{id,kind:'custom',amount}]}`.
  Legacy `allocation.currentBalance`, `liabilities.balance` and goal `saved` stay in dollars. Callers must write
  `liabilityBalances` back (`runPayRoll` does) or the next call re-bases on the stale balance.
- Tests: 10 cases (T10 to T14, T18), 68 assertions. `tests.html` 473 to 541.
