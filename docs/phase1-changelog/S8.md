# S8 - safety copy before a restore covers every part (G6W12-4)

**What changed**
- `commitBackup` (src/state/backup.js) now reads the current rows of every registered part (transactions, events, scenarios), stores them in `ft-pre-restore-parts` and the settings in `ft-pre-restore-backup`, and only then replaces anything. If either copy cannot be stored (storage full) the restore is refused with `cantKeepCopy` and nothing is changed.
- On any mid-way failure the replaced parts are put back from the in-memory rows; if a part cannot be put back the result carries `notPutBack` and the restore dialog shows `d.backup.cantPutBack` (the on-device copy still holds the old rows).
- New `undoLastRestore(store, opts)`: restores settings and every part's rows from the two on-device copies through the same commit (so it keeps a copy of what it replaces). There was no undo UI before; none added (needs a design choice, see below).
- Strings: `d.backup.cantKeepCopy`, `d.backup.cantPutBack`; the restore confirm text now says a copy of "your current data" is kept.

**Tests added:** 3 cases (S8.1 to S8.3). run-cases 2286 passed; tests.html 2675 passed.

**Left for later / design choice:** no button calls `undoLastRestore` yet. The copy is one slot, and is localStorage-bound, so very large households may hit the quota and be refused (by design).
