# S6 - security fixes from the wave 12 G6 review (G6W12-2, G6W12-9)

## G6W12-2: the sample no longer takes the one-time backup slot
F2 had the sample drop `assetDebtVersion`, so loading it ran step 5b and the chain copied the SAMPLE into
`ft-backup-pre-plan` (written once only), so a real save later got no pre-migration backup.
`buildSampleHousehold` now applies step 5b itself (`migrateAssetDebtDetail`, with its net worth check), so the
live sample has `assetDebtVersion: 1`, asset ids, suggested kinds and the inflation default and the chain has
nothing to back up. `buildSampleHousehold(today, { beforeAssetDebt: true })` is a test seam that returns the
pre-5b shape. The Erase-all change the reviewer suggested is not needed once the sample never writes the slot
(`settings-events.js` is untouched). Re-ran the reviewer's `backupkey-probe`: no backup after load, reload or erase.

## G6W12-9: step 5b tolerates non-object rows
A null, number, string or array row in `assets` or `liabilities` made `calculateTotals` throw inside the totals
check on every load. The check now builds its net worth from a throwaway copy with those rows filtered out (the
same way before and after; the cents sums already skipped them). The user's rows are never deleted or rewritten,
and names, balances and rates are never changed. Re-ran `null-probe` and the `nullRows` case of `mig-probe`: the
migration completes, version 1 is written, the odd rows stay in place.
