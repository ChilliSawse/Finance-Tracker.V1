# D2 Settings screen, Your data and the backup bundle

- New `src/ui/settings-screen.js` (+ `settings.css`, pure `settings-model.js`): Settings is a screen at `#settings-root` (a `.screen` inside the canvas, shown by the gear; any tab tap shows that tab again). Five groups and a search field: Your data (Back up, Restore, Export transactions CSV, Import rules, Erase all data), Appearance (four themes, Auto / Light / Dark through `applyAppearance`, Text size Standard 16 / Large 18 / Larger 20 px), Region and tax (Currency, and a read-only "Tax tables: 2026-27, from this app version" row from `taxTablesStatus`; no Tax year setting, FT-R-66, FT-R-86), Setup (Run setup again, Saving model opens Plan), About (Install, Privacy, Licence, Version, Fair Work pay calculator link). The `gui-settings-modal` block is deleted from `index.html`; `appearance-form.js` and `appearance.css` are deleted.
- Backup bundle v2 (`src/state/backup.js`, M-6, FT-R-74 D9): `{version:2, app, timestamp, financeData, guiSettings, transactions, events}`. Export reads transactions through B2's `exportAllTransactions`. Restore is `prepareBackup` (S1 `prepareImport`: parse, validate, sanitize, migration chain on a clone, then the part rows are cleaned: prototype keys stripped, numbers bounded, rows without a real id, date or cents amount dropped and counted) then `commitBackup` (rows swapped with an in-memory copy kept for rollback, then S1 `commitImport`: `ft-pre-restore-backup` safety copy, swap, render, save). A failure at any step puts the rows and the store back. An old bundle (no `transactions` or `events` key) restores settings only and leaves the rows on the device alone; the dialog says so. The 20 MB cap, the corrupt-save copy, the recovery panel and the migration-aborted notice are unchanged. The boot recovery panel still restores settings only.
- EXTENSION POINT for F1: `registerBackupPart({key, read, sanitize, replace})` in `backup.js`. Registering `scenarios` adds it to export, to restore (when the file carries it) and to erase-all, with no other change.
- Erase all data: one `confirmDialog` (`eraseAllData` in `settings-events.js`), then a fresh store and empty transactions and events through the same commit (so the same settings safety copy and rollback). The old "Reset to Factory Defaults" only cleared the sample batch; this now clears everything. Also removes the retired `ft-user-defaults` key and the sample flag.
- REMOVED (FT-R-64): "Save as My Defaults" and the whole user-defaults concept (`getUserDefaults`, `actionSetCurrentAsDefault`, `updateDefaultsButtonLabels`, `store.defaultFinanceData` re-pointing). Consumers checked first (U9): only the reset handler and the button label read it; boot and onboarding never did. Back up and Restore replace it. Also gone: the Reset Appearance button (Appearance has no per-user colours left to reset) and Reset to Factory Defaults (now Erase all data). `ft-user-defaults` stays in `backup.js` `RETIRED_KEYS` so the key gate still sees it; an old value is simply never read.
- Storage full (`autosave.js`): the native `alert(` is replaced by a persistent toast with a Dismiss button (`showToast(..., 'error', 0)`), once until a save works again; it tells the user to Back up first.
- `confirmAction` (native `confirm(`) deleted from `confirm.js`. `alert(` and `confirm(` no longer appear in `src/` outside test payloads.
- Install (FT-R-62): the temporary sidebar link is gone; `pwa.js` keeps the browser prompt and exposes `canInstall()` and `promptInstall()`; the About row appears only when the browser offers install.
- Import rules: the row opens a sheet with one keyword field per category (moved from the Expenses modal list, which stays until A12b).
- Run setup again dispatches a cancelable `ledger:run-setup` event; C7 listens and opens `#setup-root`. Until then a toast says setup is not available yet.
- Custom tax brackets (FT-R-97): no Settings row (the legacy editor in the Income modal is A12b's).
- `vite.config.js` defines `__APP_VERSION__` from `package.json` for the Version row. `tools/phase1-gate.mjs` `--after-d2` skips `*.test-cases.js` (test payloads such as `alert(1)` are data).
- Strings in `en-d.js` (`d.settings.*`, `d.backup.*`, `d.erase.*`, `d.storage.full`). Tests: group `settings` (D2.1 to D2.3, 41 assertions).
- Licence row reads "All rights reserved" because `README.md` says the licence is TBD (the survey said AGPL-3.0).
