# B3 plan model, migration and cutover

- `src/state/plan-migration.js`: `needsPlanMigration` (guard `dataVersion >= 2`), `migratePlanModel`,
  `ensureAllocationIdentity` (ids by slug with `-2` on collision, roles through E1's `detectRole`).
  One plan item per legacy row (`mig-ess-N`, `mig-non-N`); bills keep their id, get `anchorDue`
  and `inTotals:false` (FT-R-53); category by four ordered rules with the essential-flag check and
  the `other-essential` catch-all (created on demand); envelopes untouched (FT-R-52); `payAnchor:null`
  on sources; `planMigration {at, counts, fallbacks, reviewBills}`.
- Totals check (weekly essential and non-essential, plan against legacy, tolerance 1e-9) runs before
  anything is committed. On mismatch `dataVersion` stays unset, nothing else changes, and
  `planMigration.error` is set (returns true so the chain saves it; the same error again is a no-op).
- `calculations.js`: `dataVersion >= 2` reads `planTotals`; older data takes the unchanged legacy path.
- `defaults.js`: new data is `dataVersion:2, plan:[], rules:[]`, legacy lists empty (placeholder rows dropped).
- `sample-data.js`: `legacySampleFinanceData()` exported; the sample is piped through the chain (X-15).
- Existing fixtures adjusted without touching an assertion: `plan.test-cases.js` `sampleLike` drops
  `dataVersion` (defaults are now v2), `chain.test-cases.js` `settledData` carries `dataVersion:2`.
- Not in B3: FT-R-57 default categories belong to B2 (plan X-16).
- Tests: B3.1 to B3.9 (+ variants), 53 assertions in `plan-migration.test-cases.js`. `tests.html` 473 to 560.
