# F3 FI engine

- `src/calc/fi.js` (new, pure). Plain engine `runPlan(start, inputsFor, opts)` (yearly steps, contributions at year end, today's dollars, real rate = nominal minus `fiSettings.inflation`)
  and data readers `projectNetWorth`, `yearsToFI`, `fiNumber`, `fiNumberFrom`, `goingTowardsPerYear`, `savingsRatePlanned`, `fiAge`, `fiSummary`, `explainFi`.
  `projectNetWorth` and `yearsToFI` take `{today, years, changes, resolve}`; `resolve` defaults to `resolveAt` from `scenario.js`. With changes the data is resolved once per distinct set of active changes (`from <= date < until`), so flows and the FI number follow the plan as it stands each year; opening balances come from today's data.
- FI number = `multiple` x a year of Daily plus Splurge (`getBuckets` per pay x pays a year), planned essentials plus non-essentials when neither role exists. Smile is not counted.
- Fire money goes down E2's target list in order (debt: that debt's year-end balance; Mojo: its ladder top less its balance; Home/saver: goal less saved; Super: everything after goes to the invested pool); super (`superPct` x gross) goes to the invested pool.
- `fiNetWorth` = cash + invested + appreciating - debts - HELP; depreciating assets are in `netWorth` only (FT-R-90); HELP is a debt with its own line (FT-R-91), never a Fire target. A suggested asset kind counts as cash at 0% real (F2's rule); an invested asset with no `expectedReturn` uses the plan default.
- Years to FI: fractional in the crossing year (same annuity formula as `calculateYearsToFI`, exact for one pool), 0 when reached, `Infinity` when contributions are never positive or it is not reached in 100 years.
- `fiAge` only with `people[].birthYear`; `superNote` when anyone is under 60 (FT-R-92). Explain lines use new `f.fi.explain.*` strings in `src/i18n/en-f.js`.
- Uses F2's `assetValueAt`, `effectiveAnnualRate`, `debtStep`, `debtRateAt`; no duplication. `calculations.js` untouched.
- F1's final shapes (`segments` returns `[{from,to,key}]`, `resolveAt` adds `scenarioGoalFunds` and `scenarioOneOffs`): F3 uses only `resolveAt` and the same `from <= date < until` rule, so nothing needed changing.

## Left for later / reported

- Rates: F3 uses simple subtraction (spec convention) by passing already-real rates into F2's `assetValueAt`; F2's own `inflationPct` option uses (1+g)/(1+i)-1. Debts and HELP are deflated by division. Both are noted for the integrator.
- Scenario changes of kind `debtAdd` or changes to assets/liabilities do not alter opening balances (opening state is today's data); flows, the FI number and assumptions follow the scenario.
- Mojo and Grow shares are not flows (only Fire and super are); `data.people` is not created by anything yet (F6's assumptions sheet).
- `en-f.js` gained `f.fi.explain.*` (a likely merge touch with F1/F4).
