# S11 Small fixes from the wave 15 G6 review (info items)

## dist hygiene (G6W15-8)
- Cause: three test files and `scripts/build-themes.mjs` built a URL from `import.meta.url` with a dynamic part or a literal file name (`new URL('../' + rel, import.meta.url)`, `` `../${rel}` ``, `'../../index.html'`, `` `./scenario/${f}` ``). Vite turns each into a glob and copies every file it could match into `dist/assets`. That put `README-*.md`, `package-lock-*.json`, `index-*.html`, `tests-*.html`, `style-*.css`, `tokens.generated-*.css`, plus duplicate copies of the scenario modules and their CSS, into the build and into the service worker precache.
- Fix: those reads now use `node:path` with `fileURLToPath(import.meta.url)` under Node and a `document.baseURI` fetch in the browser (`src/pwa.test-cases.js`, `src/theme/theme.test-cases.js`, `src/ui/scenario-results.test-cases.js`, `scripts/build-themes.mjs`). No assertion changed. In a built page the two browser fetches of repo source files now get a 404 and skip (they already said "repo files cannot be read here" when a file was missing); in dev and under Node they still check the source.
- `dist` before: 94 files (with `sw.js` and Workbox); after: 75. Gone from `dist/assets`: `README-*.md`, `package-lock-*.json`, `index-*.html`, `tests-*.html`, `style-*.css`, `tokens.generated-*.css`, `answer-top-*.css`, `results-*.css`, `scenario-*.css` (the last three were duplicates of the real chunks) and the duplicate `*.js` copies.
- Tests page off the public site: `vite.config.js` leaves `tests.html` out of the inputs when `FT_NO_TESTS` is set. `deploy.yml` build job: build (with tests.html), `npm run test:ci`, then "Rebuild without the test page" (`FT_NO_TESTS=1 npm run build`) before the Pages artifact upload. The second build has no `tests.html`, no tests chunk and no precache entry for them (checked: `dist/` listing, `grep tests dist/sw.js` finds nothing). Workflow YAML parsed with the `yaml` package outside the repo: 8 build steps in the right order.
