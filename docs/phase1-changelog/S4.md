# S4 live XSS in the test page, CSP and tripwire for tests.html

- Cause: not a production sink. The `alert("1")` came from the results renderer at the bottom of `tests.html` (`tr.innerHTML = '<td>' + r.name + … + r.expected + … + r.actual`), which put raw assertion text into the live DOM. Assertions that compare hostile fixture strings (D2.2b in `src/ui/settings.test-cases.js:127` prints `<img src=x onerror=alert(1)>` as expected and actual) became real `<img onerror>` elements, each requesting `/x` (404) and running `alert(1)`. Found with a Playwright run that hooked `innerHTML`/`insertAdjacentHTML`: one sink, `tests.html` row render, two alerts.
- Fix: the results table is built with `createElement` and `textContent` only (group rows too).
- Swept `today.js`, `activity.js`, `quick-add.js`, `plan.js`, `plan-lists.js`, `plan-buckets.js`, `income-layout.js`, `settings-screen.js`, `settings-model.js`: every data interpolation into HTML already goes through `esc`/`escNum`, the escaped-params wrappers (`T`, `A` in plan-buckets), or is built with DOM nodes (`quick-add`, `income-layout`, `settings-*`). Where `t()` carries markup, each param is escaped by the caller (today.js, plan-buckets.js). No production change was needed.
- `tests.html` now has a CSP meta: the `index.html` policy with `script-src 'self' 'unsafe-eval'` (no FOUC hash, as the page has no classic inline script; `unsafe-eval` only because A4.3 runs the FOUC text through `new Function`). Inline handlers stay blocked.
- Tripwire in `tests.html`: `securitypolicyviolation` listener, and `window.alert/confirm/prompt` replaced by recorders. After the last test the page waits 400 ms for async handlers, then records one assertion ("No CSP violation and no alert/confirm/prompt during the run"); a trip after the verdict flips the summary to failed. `window.__currentCase` names the running case.
- `vite.config.js`: `ft-csp-hash` returns early for a CSP page with no inline classic script and no sha256 source (tests.html); `index.html` keeps its strict checks.
- Checked: a probe that injects `<img onerror=alert(1)>` into the live DOM now gives a CSP violation, no dialog, and a failed run. Clean run: no dialog, no `/x` request.
