# F8a What If Answer, top half, and Plan for this

- New `src/ui/scenario/answer-top.js` (registered with `registerScenarioView('answer', fn, {order: -10})`, imported from `main.js` with the new `answer-top.css`): the verdict (green Yes or amber Not yet) from the same `selected` option the cards use (`verdictFor(optionId, model)`; a different headline for Cut, Mix and Earn it, and for a slider cut), a second box for the current split, three key figures, the landing timeline, the three option cards (radio inputs, so arrow keys work) with bars, the earnings three ways from F4's `earningsThreeWays`, Fine-tune (slider, item ticks that add up on the slider and move with it, the honest note above 50% of Splurge with its two follow-ups "Smaller cut + rise" and "Smaller cut + later date"), Counting towards goals, Plan for this. Never adjusts Daily or Fire extinguisher. `computeAnswer` is pure and tested. `getAnswer(scenarioId)` and the `ft:answer-change` event give F8b the chosen option.
- `timeline.js`: `placeLabels(points, axisPx, minGapPx)` (rows, no overlap, kept inside the axis), `landingDates`, `timelineModel`, `renderTimeline` (labels and dots placed in pixels at the real width, redrawn on resize). The plan had no landing-date function, so this file owns it.
- `plan-for-this.js`: `optionChanges` (earnings become an `income` set with the rise, or `incomeAdd` when the pay source has no id; a Splurge cut becomes `expense` changes taking the ticked items to 0, until the last goal date), `pushDate`, `fundInOrder` (a `goalFund` list in due-date order; the late goals get new dates), `dropGoal`, `shrinkGoal`, `splitOffer`, `planScenario`. Every one-tap option is previewed with F4's `planGoals` before it is saved. Saving writes a NEW scenario (the scenario's own changes plus the new ones) with F1's `saveScenario`, then opens it.
- A one-tap `split` change (Smile and Splurge only) is offered only when nothing has to be earned: a rise has not landed, and its share would reach Daily and Fire by their percentages, so a split set before it would cut Splurge far below the option's figure. With earnings the screen says the split waits for the rise.
- `index.js` (outside F8a's list, minimal): `registerScenarioView(name, fn, {order})` now lets several views fill one region (each in its own `.wi-part` box), because F8a and F8b both fill Answer. `main.js`: the css import and the view import.
- Strings: one block `f.wa.*` at the end of `en-f.js` under `// F8a`. `EXPLAIN_TEXT` in `goal-planner.js` was left where it is (F8b renders it).
- Tests (own group `scenario-answer-top`, in `answer-top.test-cases.js`, registered in `test-registry.js`): F8a.1, F8a.1b, F8a.2, F8a.3, F8a.3b, F8a.3c, F8a.4 (escaping, browser only). run-cases 2496 to 2612 (+116 with the F8a group), tests.html 3033 of 3033.
- Left for later / for the integrator: the Counting ticks are kept in the view (and saved with Plan for this), not written into the scenario you are looking at (the shell has no write hook for the Answer); `openScenario` opens a saved scenario on Adjust, so after Plan for this you land on Adjust; `buildOption` in `goal-planner.js` is not exported, so `customOption` repeats its few lines; the one-tap push date looks six years ahead.
