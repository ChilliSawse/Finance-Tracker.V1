# B6 bills rewired to anchor dates

- `src/state/bills.js`: on migrated data (`dataVersion >= 2`) bills are the plan items with `anchorDue`
  (`inTotals:false`, old bill id kept as plan item id). `upcomingBills(data, days, {today, txns})` reads
  them through `billOccurrences` and `billStatus` (paid occurrences left out); results gain `dueDate` and
  `status`. New `missedBills(data, {today, txns, lookbackDays=60})` reports unpaid past occurrences as
  Missed, never rolled.
- `rollForwardBills` no longer touches plan items. Un-migrated data, and legacy `bills` rows the plan does
  not mirror (added after migration), keep the old `nextDue` roll-forward and upcoming behaviour.
- `generateBillDueEvents` still writes `ft-bill-notified` as billId to date; the date is now the occurrence
  `dueDate`, and migrated ids match because the plan item id is the old bill id. Feed event shape unchanged.
- `main.js`: comment only (the roll call is a no-op for plan items). `feed.js` untouched (A6).
- Tests: three `B6.1` cases appended to `plan.test-cases.js` (14 assertions). run-cases 814 passed, 6 skipped; tests.html 1045/1045.
