# S5 tests.html no longer touches the app's real stored data (G6W12-1)

- Cause: `tests.html` ships on the app's origin. In a real browser the tests used the real `localStorage`: A10.1 (`applyAppearance` writes `ft-theme-fouc`) and DOM-rendering tests (`recordDailySnapshot`, `checkMilestones` via `render.js`) wrote `ft-snapshots`, `ft-milestones` and `ft-theme-fouc`. A review probe showed today's net-worth point zeroed, milestones reset and the palette flipped.
- Fix, in one place (`src/test-storage-guard.js`, the first import of `tests.html`, so it runs before any app module):
  - snapshots the real localStorage, sessionStorage, the IndexedDB name list and the row counts of an existing `ledger-db`;
  - replaces `window.localStorage` and `window.sessionStorage` with in-memory stand-ins (writable, so tests that assign their own fakes still work);
  - redirects any IndexedDB `open` / `deleteDatabase` of `ledger-db` to `ledger-test-scratch-db` (the B2 group already used `ledger-test-db`; this catches any other test that reaches the default name). The scratch DB is deleted at the end.
- Tripwire: new assertion "Real localStorage, sessionStorage and IndexedDB are untouched by the run" (group "S5 real-storage tripwire"). Any difference (changed, added or removed key, new or missing database, changed row counts) fails `#summary`, so the CI gate catches it. It names the key.
- Individual tests were left as they are: with the stand-in in place A10.1 and the DOM tests write to memory only. No app (non-test) code changed.
- Proof (probe: sample real-looking synthetic state seeded in the page origin, app page first, then `tests.html`): hash of localStorage + sessionStorage + IndexedDB rows before `e5b6178714a89516`, after `e5b6178714a89516`, IDENTICAL, 2372/2372 passed. With a deliberate write to the real `ft-theme-fouc` during the run the summary fails (1 test failed) and the hashes differ.
- Tests: +1 (browser-only tripwire). `run-cases`: 2007 passed (unchanged; the tripwire is browser-only). `tests.html`: 2372/2372.
