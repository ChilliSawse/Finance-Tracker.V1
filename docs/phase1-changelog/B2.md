# B2 transaction model, manual entry storage, new default categories

- `transactions.js`: optional `status`, `bucketId`, `billMatch`, `note`, `updatedAt`, `reconciled` (documented; readers default via
  `normaliseTransaction`, which `listTransactions` applies; a legacy row reads `status 'ok'`). `source` = csv | pdf | manual | sample.
- Manual rows hash `'manual|' + id`, so two identical manual entries on one day are both stored (fixes the old hash collision).
- `updateTransaction` keeps the stored hash and stamps `updatedAt`.
- `addTransactions` now reconciles (FT-R-56): an imported csv/pdf row with the same `amountCents` as an unreconciled manual row within
  +-3 days is merged into it (manual row takes the bank hash, `reconciled:true`) and counted in the result as `merged` (result is
  `{added, duplicates, merged}`; import UI not yet showing it, D owns that). Undo of the batch leaves the manual row.
- New `exportAllTransactions()` and `importTransactions(rows)` (restore upsert, `{imported}`).
- `categories.js`: new defaults `phone-internet` (essential; telco keywords moved out of `utilities`) and `fitness` (non-essential);
  every default carries an `icon`; `categoryIcon(cat)` and `withFallbackIcons(list)` give saved categories a fallback icon.
  Existing saves are not rewritten (`migrateLedgerFields` only seeds categories when the list is empty), so the two new defaults reach
  new users and resets only.
- No IndexedDB version bump, no key or store renames.
- Tests: B2.1 to B2.6 (35 assertions, IndexedDB on `ledger-test-db`). `tests.html` 877 to 912. Node runner stays 681.
- Test edits forced by the new defaults: B3.1 "Gym falls to other" now `fitness`; B3.5 fixture bill renamed "Phone plan" to
  "Widget plan" (a phone bill now matches `phone-internet`); the legacy re-import assertion in `tests.html` marks its row `source:'csv'`.
