# S10 Make this real: security fixes from the wave 15 G6 review (G6W15-3, -4, -5)

- G6W15-3 (`src/state/scenarios.js`): one allow-list table, `REAL_FIELDS`, per change kind (expense, goal, split, assumption, income, incomeAdd, debtAdd): the fields a scenario may write and the check for each value. Checks reuse the owners: `validateAssumptions` (F6 bounds), `BILL_FREQUENCIES`, `isIsoDate`; money is 0 to 100,000,000, percentages 0 to 100, hours 0 to 168, names 1 to 120 characters. `changeRealProblem` / `changeApplyProblem` / `stepProblem` give a reason code (`number`, `range`, `date`, `choice`, `text`, `field`, `other`); `problemText` turns it into words (`f.res.mr.why.*`). `applyMakeReal` refuses a step before writing and returns `failed[{id, code, reason}]`; new plan and goal rows copy only the allowed keys (`pickRealFields`); `applySplitChanges` keys a null-prototype map. At restore, `sanitizeChange` drops a change whose field is not in the table or whose primitive value fails its check (an object value for an existing row is kept in the file and refused when applied, so F1.6b is unchanged). The Make this real list shows "Can't apply: <reason>" on a refused row with its button disabled, a toast gives the reason for a single refusal, and `describeChange` never prints "[object ...]" (also fixed a lookup that read `Object.prototype.toString` as a formatter for a field called `toString`).
- G6W15-4: a new income source is a draft in memory. `openIncomeSheet(index, {draft, prefill, onSaved})` (C6, minimal) opens the sheet on the draft and pushes it into `incomeSources` only when Save runs; a draft has no Delete; the layout switch keeps the draft and `onSaved`. `incomeStepPlan` builds the draft with `newIncomeSourceRow` from the allowed keys only. The MutationObserver clean-up is gone; the open is in try/catch.
- G6W15-5: scenarios carry `madeReal: {changeId: isoStamp}`, kept by the sanitizer (only ids of kept changes, real stamps) and saved through `updateOpenScenario` (new, `scenario/index.js`). A step already made real shows "Applied" and an "Apply again" button that asks through the danger dialog; Apply all now skips made-real steps; Undo clears the mark; editing a change clears its mark; a duplicate starts with none.
- Tests: group `scenario-make-real-safety`, 8 cases (S10.1 to S10.5 pure, S10.6 to S10.8 browser), 37 assertions. run-cases 2766 passed, 0 failed (was 2729); tests.html 3204 of 3204; sweep 25 screens ok. Reviewer probes: fields-probe now keeps 1 of 7 on restore (the object frequency), applies none, and `String(fiSettings)` works; the XSS probe shows no `[data-pwn]`, no requests, no errors, the list shows words.
- Left for later: restore keeps an object value on an existing-row `set` (refused on apply, not dropped); debt and loan sheets still rely on their own sheet validation plus the table's name, balance and rate checks.
