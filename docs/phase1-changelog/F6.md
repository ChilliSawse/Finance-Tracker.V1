# F6 Future screen

- `src/ui/future/model.js` (pure), `view.js` (pure string builders, every value escaped), `index.js` (DOM, events, sheets, saved-scenario loading), `future.css` (tokens only, `fu-` classes, ported from the round 2 mock). `src/ui/future.js` keeps C8's Income pattern and calls `mountFuture`. `main.js` gets one CSS import line. The legacy Savings and Liabilities panels are hidden by `future.css` (`#future > .legacy-panel`); A12a deletes them.
- Shows: the net worth path (inline SVG, 10 / 20 / 30 year toggle, plan line plus up to three grey dashed scenario lines, FI line and dot), four figures (now, 10, 20 years, FI number), the FI card (years to FI, ages when birth years are given, FI number, savings rate, going towards it each year, the assumptions line, notes and "add the minimum repayment" nudges, Explain this number sheet), the Assumptions sheet, the saved-scenarios list (pinned first, archived hidden behind "Show archived", On chart toggle, New scenario), the goal timeline (F4 `planGoalsFromData`, dated Smile goals only), "Things that lose value" with the HELP-counted line, and the carried cards: Debts (a card a debt that opens the F5 debt sheet, F2's good or bad `label` chip and the rate band from F5's `debtChipsHtml` rules, yearly interest, "net worth if debt-free"), HELP payoff (`projectHelpPayoff`, same logic as the old card) and tax provision (variable income only, tax pot comparison).
- Every figure comes from F1 / F3 / F4 (`fiSummary`, `projectNetWorth`, `scenarioHeadline`, `planGoalsFromData`). U33: the sample shows **28.65 years (28.6 on screen)**, FI number A$1,586,832; the copy has no number of its own (a test checks the `f.future.*` catalogue has no digits outside placeholders, and that changing `fiSettings` moves the screen).
- Only scenarios switched On chart are computed (`projectNetWorth` with the scenario's changes); at most three, a fourth gets a toast; archived ones never. The switches are kept per browser in `localStorage` `ft-future-chart` (and the horizon in `ft-future-horizon`), read and written inside try/catch. Default: none on chart.
- **Birth years** are stored as `fiSettings.birthYears: [yyyy|null, ...]`, one slot per income source (1 to 4), names from the source name's first word. F3's `fiAge` reads `people[].birthYear`, so the screen passes a read-only copy of the data with `people` filled from `birthYears` (`withPeople`); `fi.js` is untouched. The key is only written when a year is entered or the key already exists, so an untouched save adds nothing. No default added, nothing in sanitize or backup was changed (unknown `fiSettings` keys pass through).
- Assumptions sheet: multiple, expected return, inflation, optional birth years, through `openSheet`, validation in `model.js`, Undo toast restores `fiSettings`.
- Scenario rows open `openScenario(id)`; New scenario saves a blank scenario through F1's `saveScenario` and calls `openScenario`; with M0's stub (returns false) a toast says it is saved. F7 may prefer to create the row itself: then only `startNewScenario` in `index.js` changes.
- The scenarios list reloads when the Future tab button is clicked, because a tab that is not dirty is not re-rendered by `showTab`.
- Strings `f.future.*` in one block at the end of `en-f.js` (`// F6`).
- Tests: group `future` (`future.test-cases.js`, registered): F6.1 to F6.11 (model equals F3; nothing literal; list order; three-on-chart; carried cards; tax card; assumptions and Undo; chart geometry; escaping; F4 goal timeline).
- Counts: `run-cases` 2417 passed; tests.html 2806 of 2806 (browser run). Sweep: all 25 screens ok, no sideways scroll at 360 and 390.

## Fix: the Future (and Settings) screen sat below the sidebar at desktop widths

- Root cause: in `index.html` the Plan section's legacy `#expenses` panel had lost its `<div class="tab-settings-bar">` opener (its closing `</div>` stayed), so one extra `</div>` closed `<main class="canvas">` early. `#future` and `#settings-root` then parsed as children of `<body>`, under the sidebar at x=0. Found by DOM inspection (parent chain of `#future` was `body`, of `#plan` was `main > .app`). One line restored; nothing deleted. The Plan panel is a hidden legacy panel (A12a removes it).
- `tools/sweep.mjs`: at 1024 and up it now flags a screen whose main content starts left of the sidebar's right edge or below the first viewport. Before the fix it flagged Future and Settings at 1024 and 1440 (4 screens); after, all 25 are clean, light and dark.
