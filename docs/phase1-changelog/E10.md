# E10 Bucket method integration

Tests and fixes only (no new feature code beyond the Fire target edit sheet the brief asked for).

- Tax-pot comparison (`income-insights.js` `renderTaxProvisionCard`) tested on a bucket with the tax tag, on one with no id or role, and with stray rows in `allocation`. One fix: the lookup is now `a && a.isTaxProvision`, so a null row no longer throws. `getBuckets` and `leftThisPay` tested with rows lacking id, role, name, and with null/empty rows: neither throws, ids fall back, no NaN.
- Slots 5 to 10 and a repeat colour: a plan of 11 top-level buckets (Grow at slot 6, extras at 7 to 10, then a repeat with a shade) has every `--bN-bg/ink/chart/shadeN` token in all eight sets (four palettes, light and dark). Screenshots below.
- `calc/review.js`: `reviewDue` now reads `savingModel.review.lastOpenedMonth` and `buildMonthlyReview` reads `savingModel.transfers.bankSetTo` (new exported `bankSetToOf`). The older paths (`data.review`, `savingModel.bankSetTo`) are read only when the real one is absent, so the E3 tests are untouched. E9's `reviewDueFor` now calls `reviewDue` directly and `reviewModel` takes its transfers from `buildMonthlyReview` (the recompute, and two imports, are gone).
- Sample (`sample-data.js`, the bank-transfer seed lines only): `savingModel.transfers.bankSetTo` is the split rounded to the nearest A$10 per pay (Daily 2,070, Splurge 370, Smile 330, Fire 660), so the review's "Transfers to update" shows rows "was A$370.00 / now A$367.91" instead of "was A$0.00".
- Fire target edit: `updateTarget(data, id, {label, goalCents})` in `state/saving-model.js` (undoable like the other target calls; saver pots only, since the Fire card offers Remove on those only). Plan's Fire card gets an Edit link (`data-pb="fire-edit"`); `openBucketSheet('target-edit', id)` opens the Add-a-target form pre-filled (`targetSheetSpec`, `applyTargetEdit`), saves with an undo toast, and Delete uses the existing `removeTarget` with undo. Strings `e.plan.fireEdit*`, `e.sheet.targetEditTitle`, `e.fire.updated`.
- July card: `taxTablesStatus` is now also "check due" when there is no `taxCheck` record at all, a payslip-job source exists (`hasPayslipJob`: an employee source, not Variable or Self-employed, with pay set) and the date is July to September. With a record the behaviour is as before (due until the year is confirmed or dismissed). I chose the three-month window because with no record there is nothing else to anchor "a new financial year" on; without it the card would show all year to anyone who never checked. UNVERIFIED with Chilli: say so if the window should be longer or open-ended. The Settings tax row follows the same status.
- Tests: group `bucket-method` (E10.1 to E10.11, 69 assertions; E10.1 and E10.9 need a DOM and run in tests.html). `run-cases` 1797 to 1867; `tests.html` 2234 all passed.
- Screenshots (scratchpad `w12-E10`): buckets in all four palettes light and dark at 1440, sunrise at 390; Fire edit sheet light/dark at 1440 and 390; July card on 1 July.
- Noticed, not changed: a bucket with no `bankSetTo` entry (newly added) shows "A$0.00" in the transfers card.
