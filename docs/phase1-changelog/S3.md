# S3 file parser limits and correctness (security review W7: M2, M6 CSV/PDF, L1, L2, L3, L4, L7, L8)

- M2 `xlsx.js` `inflateCapped` (exported): input goes into the `DecompressionStream` in 16 KB slices while the reader drains concurrently, counts bytes and cancels/aborts the stream the moment the declared cap or the ratio guard (`maxRatio` past `minRatioBytes`) is passed. Reviewer scenario (0.5 MB deflate of 512 MB zeros, 1 MB cap): heap growth 497 MB before, 16 MB after; only 32 of 510 KB fed.
- L4 `xlsx.js`: rows actually present are counted, and `r=` must increase, so repeated `r="1"` cannot dodge `maxRows`.
- M6 CSV: `CSV_LIMITS` (15 MB, 20,000 chars per line, 256 columns, 100,000 rows); `parseCsv` throws `CsvLimitError`. `import-ui.js` checks `file.size` before reading, shows a clear message, and caps the column `<option>` build.
- M6 PDF: `PDF_LIMITS` (25 MB, 200 pages) in `pdfjs-loader.js`; `PdfLimitError`. New exported `groupRows`: sort by baseline then one sweep (O(n log n)), replacing the per-item `rows.find`.
- L1 `csv.js`: CR/DR suffix is a linear tail check; amount and date cells over 64 chars are rejected before any regex.
- L2: `parseAmountDetailed` (new; `parseAmountToCents` wraps it) returns null and `overflow` for non-finite or beyond-safe-integer cents. `normaliseRows` skips those rows with their own error and returns `outOfRange`; the import preview shows the count. `payslip.js` ignores non-finite amounts.
- L3: `toIsoIfValid` exported and checked by a `Date.UTC` round trip; the PDF year-less path uses it (31 Feb and 29 Feb in a non-leap year are skipped and counted in `skipped`, shown in the PDF preview). `pickYear` compares ISO strings, no engine parsing. `transactions.js` `shiftDate` builds from `Date.UTC` and never `Date.parse`; `addTransactions` skips rows with an impossible date and reports `invalid` (key present only when > 0).
- L7 `payslip.js` `grossDecision` (pure) + `pdf-ui.js`: an estimated gross (net + tax) always asks, a gross that differs from the stored one asks (C5 `grossProposal`), via `confirmDialog`. Decline keeps gross, net and tax still fill. A failed parse never touches gross.
- L8 `transactions.js`: count-based dedupe. Imported rows with the same key are numbered in file order (`hash`, `hash#2`, ...); a row is skipped only if its numbered hash exists. Two identical coffees import 2; re-import adds 0; an overlapping later statement adds only the extra rows. Manual rows keep `manual|id` and the +-3 day merge.
- Strings: `d.import.*` block at the end of `en-d.js`.
- Existing assertion adjusted (intent kept): `tests.html` "Normalised duplicate is skipped" now sends the duplicate in a second call, because identical rows inside one file are no longer treated as duplicates.
- Tests added: `S3.*` cases in `csv.test-cases.js` (pure, run in `tests.html`), `xlsx.test-cases.js` (M2 heap, L4) and `transactions.test-cases.js` (L8, L3). `tests.html` 1322 to 1385; `run-cases` 1040 unchanged (new cases are browser-side).
