# H2 Plan "Use these" did nothing on an own template (live bug)

Root cause: the suggested split only sets Daily, Splurge, Smile and Fire, and those four always total 100. When other buckets also hold a share (an extra bucket, Grow, Mojo on an own template), the write totalled more than 100, `setSplit` refused it, and the refusal had an empty message, so the tap showed nothing. The banner was still offered because it only compared the four.

Fix:
- `fitSuggestionToRoom` (src/calc/saving-model.js): scales the four to the room the other buckets leave (tenths, largest remainder, exact total). No change when no other bucket holds a share.
- `applySuggestedSplit` applies the fitted figures; the Plan banner shows the same fitted figures, and "Not now" remembers them.
- Every refusal now carries a plain message (new `e.bucket.suggestFail`, `e.bucket.suggestNoRoom`), so it can never fail silently again.

Test: `H2 Use these works when extra buckets hold a share` in src/ui/plan-buckets.test-cases.js (failed first, 4 assertions). Cases 2990 -> 2996.

Not changed: "left this pay" on Plan tiles. It is pool minus spend minus bills still due this pay, so with no transactions a tile can read 0 or negative when its bills are due. That is the designed calculation, not a bug in this fix. src/ui/today.js and src/state/today-model.js untouched.
