# S1 backup import and load hardening (security fixes H1, M3, M4, L5, L6, M5, M6 JSON)

- `src/state/sanitize.js` (new, pure): `sanitizeFinanceData`, `sanitizeGuiSettings`, `normaliseCurrency`,
  `safeNumber`, `prepareImport`, `commitImport`, `quarantineCorruptSave`, `buildTransactionsCsv`.
  Sanitizing strips `__proto__`, `constructor`, `prototype` at every depth, coerces known numeric
  fields (named keys plus `*Cents`, `*Pct`, `*Percent`, and `bankSetTo` values) to finite numbers
  bounded to 1e12, caps strings at 5000 characters, cuts nesting at 40 levels, and normalises
  `currency`. Stored strings are not escaped (render time does that). Null stays null (open top tax band).
- H1: `formatCurrency` validates the code (`/^[A-Z]{3}$/` and `Intl.supportedValuesOf` when present, else
  AUD), bounds the amount, and escapes its fallback output. Currency is also normalised on load and import.
- Load (`autosave.js`): sanitize, then `migrateGuiAppearance`, then the chain. A chain `{aborted:true}`
  carries on with the committed state and sets `store.loadStatus.migrationAborted` (L5); main.js shows a
  notice. An unparseable or invalid save is copied to `ft-corrupt-save-<timestamp>` once (an identical copy is
  reused), then the user is offered an export (M4).
- Import (`import-export.js`): files over 20 MB are refused before reading (M6, JSON only). Parse, validate,
  sanitize and migrate run on a clone with `raw:null` and no forceSave, so the chain writes nothing. A chain
  abort is a failed import (L5). After the user confirms, the current save is copied to
  `ft-pre-restore-backup` (one key, overwritten) (L6), the store is swapped, the UI is rendered and only then
  saved; a throw restores the previous store objects and nothing is saved (M3). `ft-backup-pre-plan` is
  no longer fed by imports. If the safety copy cannot be written, the import is refused.
- Boot (`main.js`): the boot body is wrapped; a throw opens a plain-DOM recovery dialog with Export saved
  data, Import a backup and Reset (M3). Reset and import keep a copy first.
- M5: CSV export prefixes text cells (description, category, a non-ISO date) starting with `=`, `+`, `-`,
  `@`, tab or CR (after optional leading space) with `'`. Amounts are written as plain numbers from cents
  (`-12.34`), never quoted or prefixed, so they stay numbers in a spreadsheet.
- Strings: `d.import.*`, `d.corrupt.*`, `d.recovery.*`, `d.migrate.aborted` in `en-d.js`.
- Tests: group `sanitize` (S1.1 to S1.15, 44 assertions, pure). No existing key was renamed.
