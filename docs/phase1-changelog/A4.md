# A4 theme runtime rewrite and old-theme deletion

- `src/theme/theme.js` rewritten (129 lines): `PALETTES`, `applyAppearance({palette, mode})` (sets `data-palette` and `data-mode` on `<html>`, Auto removes `data-mode`, fills the `theme-color` meta from the computed `--ground`, writes the cache), `loadTheme`, `applyStoredAppearance`, `migrateGuiAppearance`, `readAppearance`, `parseFouc`, `purgeStaleFouc`, `applyTextSize`, and `renderPaletteSwatches` (the swatch helper D2 reuses). The 13 presets, `deriveTokens`, `hex*` helpers, custom themes, harmony, font upload and the background effects are gone.
- `src/theme/appearance.js` deleted. `src/theme/appearance-form.js` (stripped modal logic: swatches, Auto/Light/Dark, Text size, Reset Appearance) and `src/theme/appearance.css` (tokens only) are new; D2 and A12b delete them.
- State: `guiSettings.theme` is the palette id, `colorMode` is `auto|light|dark`, `baseFontSize` stays. `defaultGuiSettings` shrinks to those three (no hex). Old saves keep their colour, font, effect and heading fields, unread. `migrateAppearance` runs on load (`autosave.js`), on JSON import (`import-export.js`) and on every form init (so reset to defaults and "My Defaults" are covered). First run is `sunrise` and `auto`; `pickFirstRunTheme` is gone.
- FOUC: the inline script in `index.html` is 273 bytes (limit 300), same nonce `ft-fouc-init`, CSP unchanged. It reads `{p, m}` from `ft-theme-fouc` and sets the two attributes; an old-shape value sets nothing and `purgeStaleFouc` removes it at boot (U12). `<meta name="theme-color">` added without a content value (no hex); it is filled at runtime.
- `index.html`: modal stripped to Palette, Light or dark, Text size, Currency, and Save, Reset and Backup (all ids kept, so currency, backup, restore, export CSV and both resets still work). `modal--resizable` and the drag-window wiring (`setupDraggableModal` call, its `#gui-settings-modal` CSS) are removed.
- `style.css`: the `:root` colour fallbacks are deleted, so `legacy-aliases.css` now wins (A3 note); the dead theme-switcher block (about 340 lines) is deleted. `--b1..--b4` come from the generated tokens once `data-palette` is set (A5 note).
- `scripts/build-themes.mjs` (A1 file, small extension): emits `.pal-sw[data-sw="palette-mode"]` chips so a swatch can show any palette without the page using it. Regenerated `tokens.generated.css`.
- Kept storage keys: `ft-custom-themes`, `ft-custom-fonts`, `ft-bg-effect-canvas` live on in `RETIRED_KEYS` (never read) so gate check G4 still passes.
- Tests: group `theme` (A4.1 to A4.3, 23 assertions). Node runner 704 passed; `tests.html` 900 passed; gate ok; `vite build` ok.
- Checks on the built app (synthetic data only): fresh profile, old save plus stale cache, and JSON import of an old backup each land on sunrise with a valid mode and a new-shape cache; after reload the attributes are set before app JS and no inline colour property is ever set.
- Notes: `style.css` still has other legacy hex (gate `--hex` stays red there, plus `pwa.js`, `income-statement.js`, `render-tabs.js`; not A4). An old save's stored `theme` (for example `midnight`) is rewritten only on the next real save; reads migrate it every load.
